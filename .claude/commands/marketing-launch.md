## 시작 전: 제품 마케팅 컨텍스트 확인

`.claude/product-marketing.md`가 있으면 먼저 읽고 시작한다. 이미 파악된 제품/고객/포지셔닝 정보는 다시 묻지 않는다. 파일이 없으면 `/marketing-product-marketing` 먼저 실행 권장.

---
제품·서비스 런칭 전략을 수립하고 실행 계획을 만듭니다.

**핵심 관점**: 성공하는 회사는 한 번 런칭하지 않는다. 계속 런칭한다. 작은 런칭을 반복하며 모멘텀을 만드는 것이 더 효과적이다.

**시작 전 확인사항**:

1. **런칭 대상**: 신제품? 새 기능? 새 시장?
2. **런칭 단계**: 베타 / 얼리액세스 / 정식 출시
3. **보유 채널**: 이메일 리스트, SNS 팔로워, 커뮤니티 등
4. **타겟 고객**: 누구에게 먼저 알릴 것인가?
5. **목표**: 가입자 수? 매출? 피드백?

## ORB 채널 프레임워크

| 채널 유형 | 의미 | 예시 | 특징 |
|-----------|------|------|------|
| **O**wned | 내 소유 채널 | 이메일, 블로그, 앱 알림 | 알고리즘 없음, 직접 제어 가능 |
| **R**ented | 빌린 채널 | SNS, 유튜브, 스토어 | 알고리즘 의존, 변동 많음 |
| **B**orrowed | 빌려온 채널 | 파트너, 언론, 인플루언서 | 신뢰도 높지만 일회성 |

런칭 순서: Owned 먼저 → Borrowed로 증폭 → Rented로 지속

## 런칭 5단계 프로세스

### 1단계: 내부 런칭 (Internal Launch)

- 팀, 가족, 지인에게 먼저 공개
- 목적: 명백한 버그/문제 발견
- 피드백: "뭐가 혼란스럽나요?"

### 2단계: 알파 런칭

- 소수 신뢰할 수 있는 외부 사용자 (20~50명)
- 랜딩 페이지 오픈 (웨이팅 리스트 운영)
- 목적: 핵심 가치 검증

### 3단계: 베타 런칭

- 더 넓은 테스트 그룹
- SNS, 커뮤니티에 티저 시작
- 이메일 시퀀스 구축

### 4단계: 얼리액세스 런칭

- 웨이팅 리스트 초대
- 초기 사용자 특별 혜택 (얼리버드 가격, 특별 기능)
- 목적: 수익 검증, 추천 루프 시작

### 5단계: 정식 런칭

- 셀프서브 가입 오픈
- 모든 채널 풀 가동
- PR, Product Hunt 등 외부 앰플리파이

---

## 런칭 전 체크리스트

**6주 전**
- [ ] 핵심 메시지 및 포지셔닝 확정
- [ ] 랜딩페이지 완성
- [ ] 웨이팅 리스트 이메일 시퀀스 구축
- [ ] 핵심 SNS 채널 활성화 시작

**4주 전**
- [ ] 베타 테스터에게 피드백 수집
- [ ] 고객 케이스스터디 1~2개 확보
- [ ] 언론/파트너 사전 접촉 시작

**2주 전**
- [ ] 런칭 이메일 시퀀스 완성
- [ ] SNS 예약 포스팅 준비
- [ ] 고객 지원 프로세스 준비

**런칭 당일**
- [ ] 이메일 발송
- [ ] SNS 포스팅
- [ ] 커뮤니티 공유 (Product Hunt, 해당 커뮤니티 등)
- [ ] 실시간 반응 모니터링 + 즉시 답변

**런칭 후**
- [ ] 온보딩 이메일 시퀀스 작동 확인
- [ ] 초기 사용자 인터뷰 (직접 연락)
- [ ] 다음 런칭 포인트 계획

---

## 런칭 이후 모멘텀 유지

런칭은 끝이 아니다. 계속 뭔가를 발표한다:
- 이정표 달성 (가입자 100명, 1000명 등)
- 새 기능 추가
- 고객 사례 공개
- 미디어 커버리지
- 파트너십 발표
