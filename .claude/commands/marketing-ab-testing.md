A/B 테스트를 올바르게 설계하고 결과를 해석합니다.

**시작 전 확인사항**:

1. **테스트하려는 것**: 무엇을 바꿔볼 것인가?
2. **현재 성과**: 현재 전환율, 클릭률 등 기준치
3. **트래픽/샘플 크기**: 하루/주 평균 방문자 or 이메일 발송 수
4. **목표**: 어떤 지표를 개선하려는가?

## A/B 테스트 핵심 원칙

**한 번에 하나만 테스트한다**
- 헤드라인과 버튼 색상을 동시에 바꾸면 어떤 것이 효과가 있는지 알 수 없다

**가설 기반으로 시작한다**
- "헤드라인을 기능 중심에서 결과 중심으로 바꾸면 전환율이 올라갈 것이다"
- 감으로 테스트하지 않는다

**충분히 기다린다**
- 통계적 유의성 (95% 이상) 달성 전에 중단하지 않는다
- 최소 1~2주 이상 운영 (요일 효과 포함)

## 테스트 설계 구조

```
가설: [현재 상황]에서 [변경 사항]을 적용하면
      [지표]가 [방향]으로 변할 것이다.
이유: [근거 — 데이터, 고객 피드백, 원칙]

A버전 (현재): [기존 버전]
B버전 (변형): [바꾼 버전]

측정 지표:
  주요: [하나의 핵심 지표]
  보조: [맥락 파악용 지표]
  가드레일: [나빠지면 안 되는 지표]

샘플 크기: [통계적 유의성을 위해 필요한 최소 샘플]
테스트 기간: [최소 __일]
```

## 테스트 우선순위 (ICE 점수)

아이디어가 많을 때 순위를 매기는 방법:

| 기준 | 의미 | 점수 (1~10) |
|------|------|------------|
| **I**mpact | 성과에 얼마나 큰 영향? | |
| **C**onfidence | 효과가 있을 거라는 확신? | |
| **E**ase | 얼마나 쉽게 실행 가능? | |

ICE 점수 = (I + C + E) ÷ 3

## 자주 테스트하는 항목

**높은 임팩트 (먼저 테스트)**:
- 헤드라인 및 주요 가치 제안
- CTA 문구 및 버튼 위치
- 가격 표시 방식
- 소셜 프루프 유형/위치

**중간 임팩트**:
- 이미지/영상 vs 텍스트
- 이메일 제목
- 폼 필드 수

---

## 결과 해석

**통계적 유의성 도달 후에만 결론 낸다**
- 일반적으로 95% 신뢰도 이상

**이길 때**: 승자 배포 → 다음 테스트 설계
**질 때**: 원본 유지 → 다른 가설 탐색
**무승부**: 더 기다리거나 → 더 큰 변화 테스트

**흔한 실수**:
- 너무 일찍 중단 (확증 편향)
- 여러 변수 동시 변경
- 계절/이벤트 영향 무시
