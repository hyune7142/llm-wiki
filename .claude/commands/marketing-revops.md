## 시작 전: 제품 마케팅 컨텍스트 확인

`.claude/product-marketing.md`가 있으면 먼저 읽고 시작한다. 이미 파악된 제품/고객/포지셔닝 정보는 다시 묻지 않는다. 파일이 없으면 `/marketing-product-marketing` 먼저 실행 권장.

마케팅-영업-CS를 연결하는 매출 운영(RevOps) 시스템을 설계합니다.

**시작 전 확인사항** (모르면 넘어가도 됨):

1. **GTM 방식**: 프로덕트 주도(PLG), 영업 주도, 혼합?
2. **ACV**: 평균 계약 금액은?
3. **영업 주기**: 첫 접촉부터 계약까지 평균 기간?
4. **현재 도구**: CRM, 마케팅 자동화, 일정 예약 도구 등
5. **현재 문제**: 무엇이 안 되고 있는가? (리드 누락, 팀 마찰, 데이터 단절 등)
6. **목표**: 전환율 개선? 리드 속도 개선? 처음부터 구축?

## 핵심 원칙

**단일 진실 공급원 (Single Source of Truth)**
모든 리드와 계정 데이터는 한 곳에. CRM을 정식 기록 시스템으로 정하고 모든 것을 동기화한다.

**자동화 전 정의 먼저**
스테이지 정의, 스코어링 기준, 라우팅 규칙을 종이에 먼저 정한다. 잘못된 프로세스를 자동화하면 잘못된 결과가 더 빨리 나온다.

**모든 핸드오프를 측정한다**
마케팅→영업, SDR→AE, AE→CS — 각 핸드오프마다 SLA, 추적 방식, 책임자가 있어야 한다.

## 리드 라이프사이클 프레임워크

### 스테이지 정의

| 스테이지 | 진입 기준 | 이탈 기준 | 담당 |
|---------|----------|----------|------|
| **Subscriber** | 블로그/뉴스레터 구독 | 회사 정보 제공 또는 참여 행동 | 마케팅 |
| **Lead** | 기본 정보가 있는 식별된 연락처 | 최소 적합 기준 충족 | 마케팅 |
| **MQL** | 적합도 + 참여 점수 기준 통과 | 영업 수락 또는 거절 (SLA 내) | 마케팅 |
| **SQL** | 영업이 수락하고 전화로 자격 확인 | 기회(Opportunity) 생성 또는 재순환 | 영업(SDR/AE) |
| **Opportunity** | 예산·권한·필요·타이밍 확인 | Closed-Won 또는 Closed-Lost | 영업(AE) |
| **Customer** | 계약 체결 | 확장, 갱신, 이탈 | CS |
| **Evangelist** | 높은 NPS, 추천 활동 | 지속적인 프로그램 참여 | CS/마케팅 |

### MQL 정의

MQL은 **적합도(Fit)** + **참여도(Engagement)** 둘 다 필요:
- **적합도**: 회사 규모, 업종, 역할, 기술 스택이 ICP와 맞는가
- **참여도**: 구매 의도를 보여주는 행동이 있는가 (가격 페이지 방문, 데모 신청 등)

완벽한 적합도를 가진 기업이 아무런 참여를 안 했다면 MQL이 아니다. 모든 e북을 다운받는 학생도 MQL이 아니다.

### MQL → SQL 핸드오프 SLA

- MQL 알림 담당 영업에게 전달
- 영업 **4시간 이내** (업무 시간 기준) 연락
- **48시간 이내** 자격 확인 또는 거절
- 거절된 MQL → 재순환 육성 + 거절 이유 코드 기록

## 리드 스코어링

### 스코어링 차원

**명시적 스코어링 (적합도) — 누구인가**:
- 회사 규모, 업종, 매출
- 직책, 시니어리티, 부서
- 기술 스택, 지역

**암묵적 스코어링 (참여도) — 무엇을 하는가**:
- 페이지 방문 (특히 가격, 데모, 케이스스터디)
- 콘텐츠 다운로드, 웨비나 참석
- 이메일 참여 (오픈, 클릭)
- 제품 사용 (PLG의 경우)

**마이너스 스코어링 — 비자격 신호**:
- 경쟁사 이메일 도메인
- 학생/개인 이메일
- 구독 취소, 스팸 신고
- 맞지 않는 직책 (인턴, 학생)

### 스코어링 모델 구축 순서

1. ICP 속성 정의 및 가중치 부여
2. 과거 Closed-Won 데이터에서 높은 의도 행동 신호 파악
3. 각 속성과 행동에 점수 부여
4. MQL 임계값 설정 (보통 100점 만점 중 50~80점)
5. 과거 데이터로 테스트 — 모델이 과거 성사 건을 맞히는가?
6. 시작 후 측정, 분기별 재보정

**흔한 스코어링 실수**:
- 콘텐츠 다운로드에 너무 높은 점수 (리서치 ≠ 구매 의도)
- 마이너스 스코어링 없음 (나쁜 리드가 통과됨)
- 한번 설정하고 방치 (구매자 행동은 변한다, 분기별 재보정 필수)
- 모든 페이지 방문을 동일하게 (가격 페이지 ≠ 블로그 포스트)

## 리드 라우팅

### 라우팅 방식

| 방식 | 동작 방식 | 적합한 경우 |
|------|----------|-----------|
| **Round-robin** | 영업 담당자에게 균등 배분 | 동일 영역, 비슷한 딜 규모 |
| **영역 기반** | 지역, 수직시장, 세그먼트로 배정 | 지역 팀, 업종 전문가 |
| **계정 기반** | 지명 계정은 지명 담당자에게 | ABM, 전략 계정 |
| **스킬 기반** | 딜 복잡도, 제품 라인, 언어로 라우팅 | 다양한 제품 라인, 글로벌 팀 |

### 라우팅 규칙 핵심

- 가장 구체적인 규칙 먼저, 그 다음 일반 규칙으로 폴백
- **폴백 담당자 필수** — 배정되지 않은 리드는 빠르게 식어버림
- Round-robin은 담당자 **가용성과 역량** 반영 (휴가, 할당량 달성도)
- 모든 라우팅 결정 로그 기록 (감사 및 최적화용)

### 리드 응답 속도

응답 속도는 리드 전환의 가장 큰 단일 요인:
- **5분 이내** 연락 = 자격 확인 가능성 21배 높음
- **30분 후** = 전환율 10배 하락
- **24시간 후** = 사실상 식어버린 리드

라우팅 규칙을 속도 우선으로 설계한다. 즉시 알림, SLA 초과 시 에스컬레이션.

## 파이프라인 스테이지 관리

### 파이프라인 스테이지

| 스테이지 | 필수 필드 | 이탈 기준 |
|---------|----------|----------|
| **Qualified** | 연락처, 회사, 소스, 적합도 점수 | 디스커버리 콜 예약 |
| **Discovery** | 페인포인트, 현재 솔루션, 타임라인 | 니즈 확인, 데모 예약 |
| **Demo/평가** | 기술 요구사항, 의사결정자 | 긍정적 평가, 제안서 요청 |
| **Proposal** | 가격, 조건, 이해관계자 맵 | 제안서 전달 및 검토 |
| **협상** | 수정 내용, 승인 체인, 마감일 | 조건 합의, 계약서 발송 |
| **Closed Won** | 서명된 계약, 결제 조건 | CS 핸드오프 완료 |
| **Closed Lost** | 이탈 이유, 경쟁사 (있다면) | 사후 분석 기록 |

### 파이프라인 위생 (Hygiene)

- **스테이지별 필수 필드**: 필드 미입력 시 다음 단계로 이동 불가
- **정체 딜 알림**: 평균 체류 기간의 2배 이상 머물면 플래그
- **스테이지 건너뜀 감지**: Discovery 없이 Qualified → Proposal 이동 시 알림
- **마감일 규율**: 마감일 연기 시 이유 필수 입력

### 파이프라인 지표

| 지표 | 의미 |
|------|------|
| 스테이지별 전환율 | 딜이 어디서 죽는가 |
| 스테이지 평균 체류 기간 | 어디서 막히는가 |
| 파이프라인 속도 | 하루당 파이프라인 통과 매출 |
| 커버리지 비율 | 파이프라인 / 할당량 (목표: 3~4배) |
| 소스별 성사율 | 어떤 채널이 실제 매출을 만드는가 |

## CRM 자동화 워크플로우

### 필수 자동화

- **라이프사이클 스테이지 업데이트**: 기준 충족 시 자동 진행
- **핸드오프 시 태스크 생성**: MQL 배정 시 팔로업 태스크 자동 생성
- **SLA 알림**: 담당자가 응답 시간 SLA 초과 시 매니저에게 알림
- **딜 스테이지 트리거**: 자동 제안서 발송, 예측 업데이트, Closed-Won 시 CS 알림

### 마케팅→영업 자동화

- **MQL 알림**: 담당 영업에게 리드 컨텍스트와 함께 즉시 알림
- **미팅 예약**: 잠재 고객이 예약 시 AE에게 알림
- **리드 활동 요약**: 활성 리드의 높은 의도 행동을 일일 요약으로 전달
- **재참여 트리거**: 휴면 리드가 사이트 재방문 시 영업 알림

## 딜 데스크 (Deal Desk)

### 딜 데스크가 필요한 경우

- ACV 2,500만원 이상 (또는 비표준 딜 임계값)
- 비표준 결제 조건 (Net-90, 분기별 청구)
- 커스텀 가격의 다년 계약
- 공시 가격 초과 볼륨 할인
- 커스텀 법적 조건 또는 SLA

### 승인 워크플로우

| 딜 규모 | 필요 승인 |
|---------|----------|
| 표준 가격 | 자동 승인 |
| 10~20% 할인 | 영업 매니저 |
| 20~40% 할인 | 영업 VP |
| 40% 이상 또는 커스텀 조건 | 딜 데스크 검토 |
| 다년/엔터프라이즈 | 재무 + 법무 |

## 데이터 위생 (Data Hygiene)

### 중복 제거 전략

- **매칭 규칙**: 이메일 도메인 + 회사명 + 전화번호를 기본 매칭 키로
- **병합 우선순위**: CRM 레코드 > 마케팅 자동화; 가장 최근 활동이 필드값 우선
- **정기 중복 제거**: 주간 자동 중복 제거 + 엣지 케이스 수동 검토

### 분기별 감사 체크리스트

- 중복 검토 및 병합
- 오래된 연락처의 이메일 수신 가능성 검증
- 12개월 이상 활동 없는 연락처 보관
- 라이프사이클 스테이지 분포 감사 (병목 파악)
- 샘플 세트에서 보강(Enrichment) 데이터 정확도 확인

## RevOps 지표 대시보드

| 지표 | 정의 | 벤치마크 |
|------|------|---------|
| Lead → MQL 전환율 | MQL / 총 리드 | 5~15% |
| MQL → SQL 전환율 | SQL / MQL | 30~50% |
| SQL → Opportunity | Opportunity / SQL | 50~70% |
| 파이프라인 속도 | (딜 수 × 평균 딜 크기 × 성사율) / 평균 영업 주기 | ACV에 따라 다름 |
| CAC | 총 영업+마케팅 비용 / 신규 고객 | LTV:CAC > 3:1 |
| LTV:CAC 비율 | 고객 생애 가치 / CAC | 3:1~5:1이 건강함 |
| 리드 응답 속도 | 폼 제출부터 첫 영업 연락까지 | 이상적으로 5분 이내 |
| 성사율 | Closed-Won / 총 Opportunity | 20~30% (ACV에 따라 다름) |

### 대시보드 구성

3개 뷰를 만든다:
1. **마케팅 뷰**: 리드 볼륨, MQL 비율, 소스 어트리뷰션, MQL당 비용
2. **영업 뷰**: 파이프라인 금액, 스테이지 전환, 속도, 예측 정확도
3. **경영진 뷰**: CAC, LTV:CAC, 매출 vs 목표, 파이프라인 커버리지
