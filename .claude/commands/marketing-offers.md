고객이 거절하기 어려운 오퍼(제안)를 설계합니다.

**중요 원칙**: 평범한 카피에 강한 오퍼가 평범한 오퍼에 훌륭한 카피보다 낫다. 팔리지 않는 문제는 대부분 카피가 아닌 오퍼의 문제다.

**시작 전 확인사항**:

1. **무엇을 파는가**: 서비스, 제품, 구독, 코스 등
2. **타겟 고객**: 누구에게 팔 것인가?
3. **현재 제안 방식**: 지금 어떻게 팔고 있는가?
4. **주요 반론**: 고객이 망설이는 이유는?
5. **목표 전환율 / 가격**: 원하는 수준

## 이 스킬이 맞는 경우

**잘 맞음**:
- 서비스 (컨설팅, 프리랜서, 에이전시, 프로덕타이즈드 서비스)
- 코스 (비동기, 코호트, 라이브)
- 코칭 (1:1, 그룹, 마스터마인드)
- 정보 제품 (가이드, 템플릿, 커뮤니티)
- 고가 B2B ($5K+ ACV, 영업 대화 포함)
- 다이렉트 리스폰스

**이 경우엔 `/marketing-pricing` 먼저**:
- 자체 서브 SaaS (티어 구조, 가치 지표, 패키징이 핵심)
- 마켓플레이스 (오퍼 구조가 이미 정해짐)

## 오퍼 가치 공식

```
가치 = (꿈꾸는 결과 × 달성 가능성) ÷ (소요 시간 × 노력/희생)
```

**4개 레버를 움직인다**:

| 레버 | 의미 | 가치 높이는 방법 |
|------|------|----------------|
| **꿈꾸는 결과 ↑** | 고객이 실제로 원하는 것 | 표면적 요청 뒤의 더 큰 목표에 연결. 구체적으로 이름 붙이기 |
| **달성 가능성 ↑** | 이게 될 거라고 믿는가 | 증거 (케이스스터디, 고객명, 데이터), 보증, 방법론 구체화 |
| **소요 시간 ↓** | 결과까지 얼마나 걸리는가 | 빠른 온보딩, 빠른 첫 성과, 전체 타임라인 단축 |
| **노력/희생 ↓** | 돈 외에 드는 시간/수고/리스크 | Done-for-you, 단순한 프로세스, 적은 결정, 낮은 학습 곡선 |

**핵심 인사이트**: "가격을 낮춰야 한다"는 요청의 대부분은 실제로 "분자를 올리거나 분모를 낮춰야 한다"는 요청이다.

## 오퍼의 6가지 구성 요소

### 1. 핵심 가치 (Core Deliverable)

고객이 실제로 받는 것. 기능이 아닌 결과로 표현한다.

```
❌ "마케팅 컨설팅 10시간"
✅ "3개월 내 리드 2배 달성 플랜 + 주간 코칭"
```

### 2. 보너스 스택 (Bonus Stack)

핵심 가치를 보완하는 추가 혜택. 각 보너스는 독립적으로 가치 있어야 한다.

```
보너스 1: [구체적인 것] — 원래 가격 [N]만원
보너스 2: [구체적인 것] — 원래 가격 [N]만원
```

### 3. 보증 (Guarantee)

리스크를 우리가 떠안는다. 고객의 두려움을 제거한다.

| 보증 유형 | 예시 |
|-----------|------|
| 환불 보증 | "30일 이내 환불 보장" |
| 결과 보증 | "[목표] 달성 못하면 환불" |
| 지속 지원 | "[기간] 내 추가 지원 보장" |

### 4. 희소성/긴급성

진짜 희소성만 사용한다. 가짜 카운트다운은 신뢰를 깎는다.

- 한정 수량 (실제 처리 가능 인원)
- 실제 마감 기한 (이벤트, 가격 인상)
- 얼리버드 혜택

### 5. 이름 (Naming)

오퍼 이름이 가치를 전달해야 한다.

```
❌ "마케팅 패키지 A"
✅ "3개월 런칭 가속 프로그램"
```

### 6. 가격 & 결제 구조

- 높은 가격 앵커 먼저 제시
- 분할 납부 옵션 (월납 vs 연납)
- 연납 할인 명확하게

## 오퍼 강화 체크리스트

- [ ] 결과가 명확한가? (기능이 아닌 결과)
- [ ] 보증이 있는가? (리스크 제거)
- [ ] 비교 기준이 제시되었는가? (앵커링)
- [ ] 지금 해야 하는 이유가 있는가? (긴급성)
- [ ] 반론이 처리되었는가?
- [ ] 다음 단계가 명확한가?
