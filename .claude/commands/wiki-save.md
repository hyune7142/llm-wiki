현재 대화 내용이나 인사이트를 위키 노트로 파일링합니다.

**진행 방식 (Claude에게)**:

사용자가 `/wiki-save`를 실행하면:

1. **저장 대상 파악**: 아래 중 무엇을 저장할지 파악한다. 명확하지 않으면 질문한다.
   - 현재 대화에서 나온 핵심 인사이트 / 결론
   - 특정 개념·용어 설명
   - 질의응답 기록
   - 세션 전체 요약

2. **노트 타입 결정** (자동 판단, 애매하면 물어봄):
   - `concept` — 아이디어, 패턴, 프레임워크, 방법론
   - `question` — 질의응답 기록 (`wiki/questions/question-[슬러그].md`)
   - `entity` — 사람, 조직, 제품, 도구
   - `comparison` — A vs B 비교 분석

3. **페이지 작성**:
   - 프론트매터 스키마 적용 (타입에 맞는 `_templates/` 템플릿 참조)
   - 저장 위치: `wiki/[타입]s/[타입]-[슬러그].md`
   - 위키 내 관련 페이지는 `[[페이지명]]` 형식으로 연결
   - 대화에서 나온 표현을 그대로 살려서 작성 (요약하되 원본 뉘앙스 유지)

4. **인덱스 업데이트**: 가능하면 `node scripts/wiki-sync-index.mjs`로 `wiki/index.md`를 재생성한다. 스크립트를 쓸 수 없으면 `| 파일 | 제목 | 타입 | 태그 | 키워드 | 요약 | updated |` 형식으로 새 페이지 행을 추가한다.

5. **검증**: `node scripts/wiki-lint.mjs`를 실행하고 오류가 있으면 수정한다. 검증 중 오류를 실제로 수정한 경우에만 `/wiki-lint`의 기록 정책에 따라 `wiki/log.md`와 `wiki/hot.md`를 갱신한다.
6. **운영 로그 정책**: save 자체만으로는 `wiki/log.md`와 `wiki/hot.md`를 변경하지 않는다. 저장은 지식 페이지 생성이지만 운영 로그 누적 대상은 아니다.

저장 완료 후 파일 경로와 제목을 보여준다.
